Architecture: 2-Stage Pipeline

Stage 1: Intent Analysis

/api/intent-analysis (Claude Haiku)

Input: User message + conversation history

Claude determines:

  • Is query vague ("shoes") or specific ("Nike Air Max")?
  • What are optimized search keywords?
  • Do we need more details?
Stage 2: Smart Filtering

/api/filter-results (Claude Haiku)

Input: 100 products from Fiber + conversation history

Claude ranks by:

  • Relevance to user request
  • Price + cashback value (combined)
  • Quality (ratings, reviews)
  • User demographics (if mentioned: gender, budget, brand)

Context: The Secret Sauce

We don't use a database for user preferences. We use conversation history.

Session Memory (React State):

[
{ id: 1, type: 'user', text: "I'm looking for shoes" },
{ id: 2, type: 'assistant', text: "...", products: [...] },
{ id: 3, type: 'user', text: "Show me blue ones" },
{ id: 4, type: 'assistant', text: "...", products: [...] }
]

This history is passed to Claude on EVERY request
Why This Works
  • ✓ Claude understands "blue ones" = blue shoes from previous context
  • ✓ Claude remembers "you looked at Nike last time"
  • ✓ Claude learns user style (brand preference, budget, quality focus)
  • ✓ Session scope: Lost on refresh (stateless, no storage)

Privacy: Built Into Architecture

❌ What We DON'T Store

  • User personal data (name, email, location)
  • Wallet addresses (session memory only)
  • Search history (not persisted)
  • Preferences profile (inferred from conversation)
  • Behavioral data (no cross-session tracking)

✅ What We Use

  • Current conversation (in memory)
  • Fiber API responses (real-time)
  • Claude analysis (ephemeral)
  • Session context only (lost on refresh)
  • No databases, no profiling
Bottom line: We can't spy on users because we don't store their data. Privacy by architecture, not by policy.

Q&A

Q: How do you prevent Claude from hallucinating?

A: Claude doesn't generate products—it filters/ranks real Fiber data. Source of truth is Fiber API's 100-product response.

Q: What if Claude's filtering is wrong?

A: Graceful fallback: Show top 10 by price (cheapest after cashback). Claude is a feature, not a requirement.

Q: Can users opt-out of Claude filtering?

A: Yes—always fallback to price-based ranking. Future: explicit toggle in settings.

Q: How much conversation history do you keep?

A: Only current session (browser memory). On refresh, history is lost. Intentional for privacy & stateless design.
